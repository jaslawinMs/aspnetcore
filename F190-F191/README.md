## F190: nullable page links are not arbitrary deferred enumerables

[HANDOFF.json](evidence/F190/HANDOFF.json) and [producer-matrix.json](evidence/F190/producer-matrix.json) identify **16 actual non-null initializer sites**: twelve string-array sites of sizes 4, 5, 6, 7, or 10, and four real `Concat`/`Append` pipeline sites of size 4 or 5. Their underlying menus are three-element lists/arrays, with a one-element array footer. Seven Blazor construction sites omit `Links`; the outer page iterator is not a deferred `Links` producer.

The dependency-pinned `Count`, `Concat`, and `Append` implementation source obtains these counts through collection metadata without enumerating elements. With the default `IsSizeOptimized=false` source configuration, `Any` uses the same cheap-count chain. Its alternate configuration may enumerate instead. No actual test-host switch, JIT, executing runtime, allocation, or small constant-factor cost was observed.

The consumer first checks the page response, then invokes secondary HTTP/HTML/link validation only for positive non-null link counts. Positional link checking still enumerates in order. Null/empty handling, request/parser/assertion ordering, and mutable property lifetimes were traced but not executed or changed. No artificial one-shot, throwing, side-effecting, huge, or empty producer was substituted for the actual fixtures.

The **67 passing [source checks](evidence/F190/source-audit-results.json)** are offline qualification, not native test assertions. The entire ProjectTemplates subtree matches across the recorded source pins. Fourteen complete LINQ source snapshots are bound to `dotnet/dotnet` dependency-source commits `dfd6ac738610ea05f42e704be82b386e71052e12` and `4f30608f5e5220a5671e61f4bd5dece130657f47`; their blob IDs are independently recomputed. These are **source/dependency provenance, not loaded runtime identities** or a complete external raw-commit/tree archive. No material traversal-saving candidate was established, and no constant-factor performance equality is claimed.

## F191: the array survives the interface conversion

[HANDOFF.json](evidence/F191/HANDOFF.json) records the real producer: diagnostics are filtered into a temporary `List<Diagnostic>`, sorted and materialized with `OrderBy(...).ToArray()`, the temporary list is cleared, and the array is returned to the only located direct caller of the verifier. That array retains its `IList<Diagnostic>`/`ICollection<Diagnostic>` implementations when passed as `IEnumerable<Diagnostic>`; `ElementAt(int)` uses indexed access. The reported repeated non-indexed traversal is absent on these located producer paths.

Complete source inventories identify **189 Original and 201 Default canonical call sites**, with source-declared expected diagnostic counts **0-4**. Those numbers are not runtime populations, discovered/passing tests, or the reason indexing is valid. The four verifier/helper files match across source roles. No diagnostic count, native analyzer-suite result, runtime identity, allocation, or timing was observed.

Preserved attempts include an unavailable Python Store alias, an initially unresolved collection-expression inventory later resolved by source inspection, and bounded/unresolved LSP metadata responses. No dependency was installed and no missing native prerequisite was invented. The [qualification checks](evidence/F191/SOURCE_QUALIFICATION_CHECKS.json) remain explicitly source-only.
