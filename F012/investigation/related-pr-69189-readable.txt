Reduce SignalR send, reconnect, authorization, and SSE overhead.

## Description

This changes five paths without introducing public APIs:

- Use indexed connection lookup for `SendConnectionsAsync` with at most 16 target IDs, with allocation-free duplicate suppression and shared serialization. Larger lists retain the original scan to avoid target-sized allocations and unbounded deduplication work.
- Track the last `MessageBuffer` block so appends no longer traverse the retained reconnect backlog. This is shared by the server and .NET client.
- Cache successful combined hub-method authorization policies per method and provider identity, only when `AllowsCachingPolicies` permits it. A `ConditionalWeakTable` avoids retaining scoped/transient providers. Authorization is still evaluated against the current user, resource, and scoped services on every invocation; failed/canceled combinations are not cached.
- Initialize per-invocation cancellation tracking only when needed. Unknown cancellation messages do not initialize it; `ConnectionAborted` remains independent of this dictionary.
- Format multiline SSE messages into a pooled contiguous buffer and perform one output write. A per-segment LF count gives a safe size upper bound; only the actual formatted bytes are written. The rental remains owned until the output completes and is returned on success, failure, or cancellation.

Adds 10 benchmark classes covering 58 scenarios, including adverse inputs and serial/concurrent group churn. **Group membership code is unchanged**; those benchmarks establish controls and future optimization coverage.

The merge of `main` preserves its expanded authorization metadata support (`IAuthorizeData`, `AuthorizationPolicy`, and `IAuthorizationRequirementData`). Metadata that produces no policy remains allowed; null results are not inserted into the cache.

### Tradeoffs and uncertainty

- **Dense small fanout is slower.** The 10-of-10 case is +23.7% in the full run and +3.6% in the reverse-order repeat (785.52 -> 813.77 ns). The magnitude varies; this is not an across-the-board send improvement.
- **One-use cacheable scoped providers pay for cache insertion without reuse:** +17.0% / +14.7% in the two pairs, with about 26 additional allocated bytes per invocation. The simple, provider-correct cache deliberately does not add an admission heuristic. Warm singleton authorization improves 20.1% / 17.4%, saving 656 B per invocation.
- **Used cancellation tracking costs 32 B more per connection.** Savings apply only to connections that never need per-invocation tracking, not merely those that never receive cancellation.
- **One-byte SSE segmentation is not a demonstrated throughput win:** +6.6% in the full run, -0.3% in the repeat. Allocation falls substantially in both.
- **LF-count sizing can over-reserve for CRLF.** Each trimmed CR leaves an extra reserved byte; at an array-pool boundary this can select the next bucket, potentially doubling rented capacity. Only actual output is sent. Pooling also trades repeated managed allocations for pool-retained capacity; the allocation column is not a peak-memory measurement.
- **Concurrent group timings are noisy controls, not optimization claims.** No production group code changed. The 8-worker/1,024-member shared case changes +10.1% then -3.8%; the independent case changes +1.2% then +14.8% with high variance in the latter run. Small control differences, including non-cacheable authorization, should not be interpreted as reliable gains.

### Methodology

Apple M2 Max, Arm64, 12 physical/logical cores; macOS 26.6.2 (25G83). SDK `11.0.100-preview.6.26318.108`, runtime `.NET 11.0.0 (11.0.26.36017)`, BenchmarkDotNet 0.13.0, **Release** builds. `--config debug` selects the repository's in-process benchmark toolchain; it does not mean Debug compilation.

Both builds use identical new benchmark sources and dependencies. A temporary MSBuild compile-item overlay supplies the six production files from the baseline commit, including the shared buffer in both server/client and the formatter linked into the benchmark assembly. Separate output snapshots prevent loading current dependencies into the baseline. Source fingerprints, substitution manifests, and baseline/current assembly markers were checked.

Each case uses 10 warmups, 7 measured iterations, and a 200 ms target iteration time. All 58 scenarios were run before then after, sequentially with no overlapping builds. A 24-case subset was then rerun after then before. Tables below retain the complete primary results and the separate repeat, rather than selecting the fastest run. Percentages are `(after / before - 1) * 100`; negative is faster.

Results are mean time and managed allocation per operation, **not end-to-end network throughput**. Reconnect burst results are per appended message (`OperationsPerInvoke = 32`). Group results are per add/remove pair (concurrent batches contain 1,024 pairs and include scheduling costs). The authorization benchmark waits for successful invocation completion, not just dispatch enqueueing. The SSE output benchmark verifies bytes written and exercises both actual synchronous and forced asynchronous sinks.

`OriginalScan` is a copied original-algorithm control; `IndexedSend` invokes the actual lifetime-manager API in each build (and takes the original-scan fallback for these >16-target adverse cases). Compare each method across builds, not the two methods as if they were the before/after pair. Small nonzero allocations in longer-running cases can include measurement/background noise. Concurrent group allocation totals also vary between runs; compare within a pair.

### Reproduction

Build once for each production revision while keeping the benchmark sources identical, then run each captured output separately with the same SDK/runtime:

```bash
source activate.sh
./src/SignalR/build.sh -c Release --no-restore \
  --projects "$PWD/src/SignalR/perf/Microbenchmarks/Microsoft.AspNetCore.SignalR.Microbenchmarks.csproj" \
  --verbosity quiet

dotnet artifacts/bin/Microsoft.AspNetCore.SignalR.Microbenchmarks/Release/net11.0/Microsoft.AspNetCore.SignalR.Microbenchmarks.dll \
  --config debug \
  --filter '*AdverseBenchmark*' '*ServerSentEventsFormattingBenchmark*' \
           '*ServerSentEventsOutputBenchmark*' '*HubConnectionContextCreationBenchmark*' \
           '*HubMethodAuthorizationBenchmark*' '*SendConnectionsBenchmark*' \
           '*MessageBufferBenchmark*' '*HubGroupList*Benchmark*' \
  --warmupCount 10 --iterationCount 7 --iterationTime 200 \
  --memory --exporters json --artifacts "$PWD/artifacts/benchmark-results"
```

The repeat filters were `*SendConnectionsBenchmark*`, `*HubMethodAuthorizationBenchmark.Authorized*`, `*ServerSentEventsAdverseBenchmark*`, `*ServerSentEventsOutputBenchmark*`, and `*HubGroupListConcurrencyBenchmark*`. Use distinct artifact directories for each run. The baseline commit alone does not contain these new benchmark classes.

## Validation

After the final test-only reduction, the focused run covered 321 SignalR server cases (320 passed and 1 skipped) and 34 SSE formatter/transport cases (all passed). Every retained theory row executed successfully. No pre-existing tests, production code, or benchmarks were changed by the reduction.

The added test set now has 13 methods across six files. The latest trim reduced it from 28 methods and 998 added lines to 13 methods and 514 added lines (484 fewer lines, about 49%), following the earlier 97-line reduction. It consolidates targeting and serialization checks, keeps one ACK/append/replay scenario, and removes redundant authorization permutations, GC/concurrency stress scaffolding, and pool-capacity assertions.

Retained regression coverage checks duplicate/missing/case-sensitive recipients and shared serialization on both sides of the 16/17-target boundary; pending writes and existing cancellation behavior; ordered replay after partial/full ACKs and block reuse; policy-cache opt-in, provider/method isolation, mixed metadata, null/failure retries, and authorization with fresh scoped services/resources on every invocation; the handler-level no-allocation path; explicit CR/LF and Unicode framing with contiguous/fragmented input, one exact-length write, and buffer ownership until asynchronous output completes or cancels.

Before these test-only reductions, the shared .NET client multi-target build (`net11.0`, `netstandard2.0`, `netstandard2.1`, and `net462`), Release microbenchmark build, and authorization benchmark smoke run succeeded with the merged dependencies. Performance measurements were not rerun; all before/after tables and their pre-merge provenance remain unchanged.
